# Experiment 2 red-to-blue two-shelf runtime test report

Ran the TurtleBot4 VMware simulation locally against the merged red-to-blue route, recording RViz and the action terminal while the robot navigated from `(-11.25, -10.5)` to `(0.4, -10.5)` around two shelf structures.

## Escalations / caveats

- The recording tool's processed annotated summary was only `40.709 s`, so it is **not** used as acceptance evidence. I instead concatenated the raw recording segments with stream copy only and muxed annotation subtitles into an MP4 without changing playback speed; the delivered full-speed video is `1336.604 s`, longer than the `1248.075 s` action wall duration.
- The VMware startup validator again reported an initialization-only `/clock` gap during heavy world loading. After loading, `/clock` was stable at about `20 Hz`, and the runtime test proceeded only after the post-load stability, localization, and Nav2 checks passed.

## Assertions

- Passed — System Python was ROS-compatible: `Python 3.10.12`.
- Passed — Post-load `/clock` stayed near `20 Hz`: observed averages `19.967`, `19.947`, `20.002`, `19.997 Hz`.
- Passed — Localization was stable: `position_drift=0.000 m`, `yaw_drift=0.000 rad`, `scan_alignment=1.000`.
- Passed — Nav2 loaded the custom planner: `/planner_server GridBased.plugin = tb4_astar_planner/AStarPlanner`; planner, controller, and BT navigator were all `active [3]`.
- Passed — Accepted global path met the two-shelf criteria: `poses=787`, `path_length=24.489 m`, `detour_ratio=2.102`, `lateral_deviation=7.055 m`, `direct_obstacles=4`.
- Passed — The robot visibly cleared the first and second shelf ends without collision or shelf penetration.
- Passed — The same NavigateToPose action reached `SUCCEEDED`: `terminal_status=4`, `wall_duration=1248.075 s`.
- Passed — Full-speed raw deliverable is continuous and unaccelerated: video duration `1336.604 s`, H.264 at `15 fps`, stream-copy concatenation, no `setpts`, trim, or frame dropping.
