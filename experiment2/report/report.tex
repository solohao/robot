\section*{摘\quad 要}
\addcontentsline{toc}{section}{摘要}
本实验面向 TurtleBot4 移动机器人，在 Ubuntu 22.04 与 ROS 2 Humble 环境下构建
Ignition Gazebo 仿真系统，完成环境建图、基于静态地图的自定位、代价感知 A*
全局路径规划以及 Nav2 闭环自主导航。针对初版“建图范围小、路径短、雷达云漂移”
的反馈，在原系统上增加扩展建图路线、地图覆盖率门槛、AMCL/TF/LaserScan 稳定性
检查以及长距离导航 action 验收，形成可自动判定的证据链。

扩展 SLAM 验收中，机器人累计行程达到 5.00 m，已知栅格增加 58,506 个，分别满足
不少于 5.0 m 与 15,000 个栅格的门槛。定位前置检查连续观察 15 s，实测
\code{map -> base\_link} 位置漂移为 0.000 m、航向漂移为 0.000 rad，
LaserScan 端点与地图占用栅格匹配率为 96.5\%，明显高于 35\% 下限。

全局规划仍使用按照 \code{nav2\_core::GlobalPlanner} 接口实现的 C++ A* 插件。
长距离目标设为 $(-7.0,-10.0,0.0)$，实测全局路径包含 370 个位姿，长度为
13.460 m；同一 \code{NavigateToPose} action 经 385.981 s 墙钟时间进入
\code{SUCCEEDED (4)}。最终提交视频完整覆盖目标发送前至到达目标后的全过程，
时长 443.934 s，未使用加速、抽帧或删减。上述结果均来自仿真环境，不等同于实体
TurtleBot4 性能验证。

\noindent\textbf{关键词：}TurtleBot4；ROS 2；Ignition Gazebo；SLAM Toolbox；
AMCL；Nav2；A*；自主导航

\section{实验目的与要求}

\subsection{实验目的}
\begin{enumerate}
  \item 了解 TurtleBot4 机器人的主要硬件构成及其工作原理；
  \item 掌握 TurtleBot4 与远程主机之间的连接原理；
  \item 掌握 Ignition Gazebo 与 RViz 仿真软件的使用；
  \item 掌握 ROS 2 机器人操作系统的基本操作；
  \item 掌握移动机器人自主导航功能的基本实现原理。
\end{enumerate}

\subsection{仿真实验要求}
在 Ignition Gazebo 仿真环境中实现 TurtleBot4 机器人的自主导航。仿真内容包括：
\begin{enumerate}
  \item 调用机器人控制系统内置的 SLAM 模块对周围环境进行地图建模；
  \item 调用自定位模块，在地图坐标系下获得机器人位姿；
  \item 编程实现全局路径规划算法，并接入导航系统；
  \item 在 RViz 中设定初始位姿和导航目标，使机器人在仿真环境中自主运动并绕开障碍；
  \item 采集地图、路径、动作终态和目标容差等客观证据，分析实验结果。
\end{enumerate}

\subsection{实验范围说明}
本报告仅覆盖课程要求中的\textbf{仿真部分}。真实 TurtleBot4、实验室无线网络和
Discovery Server 不在当前测试环境中，因此不将实机连接或实机自主导航列为本报告
的完成项。代码包中保留了实机启动入口，便于后续将相同 A* 插件和 Nav2 参数迁移到
实体机器人。

\subsection{TurtleBot4 主要硬件构成}
TurtleBot4 标准版以 iRobot Create 3 为移动底盘，采用两轮差速驱动并通过轮速编码器
与惯性测量信息生成里程计；上位计算单元为 Raspberry Pi 4B，负责运行 ROS 2 节点、
传感器驱动与高层任务。标准传感器包含 RPLIDAR A1M8 360° 二维激光雷达和 OAK-D-Pro
深度视觉相机。RPLIDAR 输出的 \code{/scan} 是本实验建图、定位和局部避障的主要环境
观测；Create 3 底盘输出 \code{/odom}，并接收 \code{/cmd\_vel} 速度指令。

差速底盘的平面运动学可写为
\begin{equation}
  v=\frac{r}{2}\left(\omega_R+\omega_L\right),\qquad
  \omega=\frac{r}{L}\left(\omega_R-\omega_L\right),
  \label{eq:differential}
\end{equation}
其中 $r$ 为驱动轮半径，$L$ 为轮距，$\omega_R$ 与 $\omega_L$ 分别为左右轮角速度。
机器人平面位姿由 $x$、$y$ 和航向角 $\theta$ 构成，其连续时间模型为
\begin{equation}
  \dot{x}=v\cos\theta,\qquad
  \dot{y}=v\sin\theta,\qquad
  \dot{\theta}=\omega.
\end{equation}
仿真器对上述运动学、碰撞和传感器过程进行数值积分，ROS 2 节点通过相同接口使用
仿真数据，因此算法层与实机层可以共享。

\subsection{远程主机连接原理}
实体 TurtleBot4 包含 Create 3 与 Raspberry Pi 两个计算单元，两者通过 USB-C 建立
供电和以太网连接；远程 PC 通过 Wi-Fi 加入机器人网络。ROS 2 使用 DDS 进行节点
发现与数据分发，TurtleBot4 可使用 Simple Discovery 的组播发现，也可由 Fast DDS
Discovery Server 集中管理参与者。远程主机需要与机器人使用兼容的
\code{ROS\_DOMAIN\_ID}、RMW 实现和 Discovery Server 配置，随后即可订阅
\code{/scan}、\code{/odom}，并调用 Nav2 action。

本次单机仿真中，Gazebo、SLAM、AMCL、Nav2 和 RViz 位于同一 ROS 2 域内，节点通信
机制与远程连接一致，只是数据链路由本机回环网络代替 Wi-Fi。由此可以在没有实体
硬件时验证 ROS 2 接口、消息类型、TF 树和 action 生命周期。

\subsection{SLAM Toolbox 增量建图}
SLAM 阶段由激光扫描与里程计估计机器人轨迹，并建立二维占据栅格地图。对于栅格
$m_i$，占据概率可用 log-odds 形式递推：
\begin{equation}
  l_{t,i}=l_{t-1,i}
  +\log\frac{p(m_i\mid z_t,\bm{x}_t)}{1-p(m_i\mid z_t,\bm{x}_t)}
  -l_{0,i},
  \label{eq:occupancy}
\end{equation}
其中 $z_t$ 为第 $t$ 帧激光观测，$\bm{x}_t$ 为机器人位姿。SLAM Toolbox 同时维护
激光关键帧和位姿图，通过扫描匹配与图优化校正累积误差，并发布
\code{map -> odom} 变换。实验以同步模式运行，建图后使用
\code{nav2\_map\_server/map\_saver\_cli} 保存地图。

\subsection{AMCL 自定位}
导航阶段加载与 warehouse 世界对应的静态地图，AMCL 使用粒子滤波估计机器人在
\code{map} 坐标系中的位姿。粒子集合
$\{\bm{x}_t^{[k]},w_t^{[k]}\}_{k=1}^{N}$ 依次经历运动采样、激光观测加权和重采样。
在 RViz 中通过 \code{2D Pose Estimate} 发布 \code{/initialpose}，使粒子在初始
位置附近收敛；AMCL 随后发布 \code{map -> odom}，与底盘的
\code{odom -> base\_link} 共同构成导航所需 TF 链。

\subsection{代价感知 A* 全局路径规划}
自定义规划器继承 \code{nav2\_core::GlobalPlanner}，由 pluginlib 导出并在 Planner
Server 中注册为 \code{GridBased}。算法在全局代价地图上执行 A* 搜索，节点评价函数为
\begin{equation}
  f(n)=g(n)+h(n),
\end{equation}
其中 $g(n)$ 是从起点到节点 $n$ 的累计代价，$h(n)$ 是到目标的启发式估计。八连通
栅格采用 octile distance：
\begin{equation}
  h(n)=\sqrt{2}\min(\Delta x,\Delta y)
  +\max(\Delta x,\Delta y)-\min(\Delta x,\Delta y).
\end{equation}

为使路径远离膨胀代价较高的障碍边缘，进入栅格 $n$ 的边权定义为
\begin{equation}
  c(n)=d\left(1+\lambda\frac{\min(C(n),252)}{252}\right),
  \label{eq:cost}
\end{equation}
其中 $d$ 为直移距离 1 或对角距离 $\sqrt{2}$，$C(n)$ 为 Nav2 代价地图值，
$\lambda=2.0$ 为代价惩罚系数。算法将代价不小于 253 的栅格视为致命障碍，并禁止
未知区域。对角扩展时同时检查相邻两个正交栅格，任一不可通行则拒绝该对角边，
从而避免路径从障碍角点之间穿过。

\subsection{Nav2 闭环执行}
RViz 的 \code{Nav2 Goal} 工具向 BT Navigator 发送
\code{NavigateToPose} action。Planner Server 调用 A* 生成
\code{nav\_msgs/Path}，Simple Smoother 对路径进行平滑；DWB 局部控制器结合局部
代价地图产生 \code{/cmd\_vel\_nav}，Velocity Smoother 以 20 Hz 限制速度和加速度
后输出 \code{/cmd\_vel}。机器人运动产生新的激光与里程计，形成完整反馈闭环。

\subsection{仿真启动模式}
统一入口通过 \code{slam} 参数提供两个互斥流程：
\begin{itemize}
  \item \code{slam:=true}：启动一套 SLAM Toolbox，不启动 AMCL；
  \item \code{slam:=false}：加载静态地图并启动 AMCL，不启动 SLAM Toolbox。
\end{itemize}
官方模拟器 include 被包装在 scoped group 中；子作用域内分别将
\code{localization}、\code{slam} 与 \code{nav2} 置为 false。这一设计既阻止
父级 \code{slam:=true} 泄漏到官方 spawn 流程而产生重复节点，也阻止子级参数反向
覆盖项目自身的模式选择。

ros2 run tb4_experiment_bringup vmware_simulation slam:=true
\end{lstlisting}
启动后确认仅存在一个 \code{/slam\_toolbox}，不存在 \code{/amcl}，且
\code{/map} 的唯一发布者为 SLAM Toolbox。在两个独立终端启动覆盖率检查与扩展路线：
\begin{lstlisting}[language=bash]
ros2 run tb4_experiment_bringup validate_slam_coverage \
  --min-distance 5.0 --min-known-cell-delta 15000

ros2 run tb4_experiment_bringup run_extended_mapping_route
\end{lstlisting}
路线在起点和终点各执行一周原地扫描，并按相对起点
$(-3,0)\rightarrow(-3,-10)\rightarrow(-7,-10)$ 穿过多个通道；前方
0.55 m 内出现障碍时立即停止。路线速度发布到 \code{/cmd\_vel\_nav}，由已激活的
Velocity Smoother 统一输出 \code{/cmd\_vel}，避免两个发布者互相覆盖。只有覆盖率
检查输出 \code{[PASS]} 后才保存扩展地图：
\begin{lstlisting}[language=bash]
ros2 run nav2_map_server map_saver_cli \
  -t /map -f experiment2/maps/extended_lab_map
\end{lstlisting}

\subsection{稳定 AMCL 初始化与规划器检查}
结束建图流程并完全关闭旧 Gazebo、RViz 与 ROS 2 launch 进程。A* 导航验证独立使用
与 warehouse 世界严格匹配的官方静态地图，以避免未完整探索区域影响全局路径。
启动文件默认加载 \code{localization\_stable.yaml}：初始位姿固定为 $(0,0,0)$，
启用 beam skipping，并将粒子数范围设为 750--2500。为避免慢速虚拟机在 AMCL
建立 \code{map -> odom} 前激活 Nav2，先只启动 Gazebo、AMCL 与 RViz：
\begin{lstlisting}[language=bash]
ros2 run tb4_experiment_bringup vmware_simulation start_nav2:=false
\end{lstlisting}
发送目标前执行稳定性检查：
\begin{lstlisting}[language=bash]
ros2 run tb4_experiment_bringup validate_localization_stability
\end{lstlisting}
该节点等待 \code{/scan} 与 \code{map -> base\_link}，连续计算 15 s 的位置漂移、
航向漂移，并将 LaserScan 端点投影到地图栅格中计算占用匹配率。检查通过后，在
第二个终端启动 Nav2：
\begin{lstlisting}[language=bash]
PARAMS="$(ros2 pkg prefix tb4_experiment_bringup)/share/\
tb4_experiment_bringup/config/nav2_astar.yaml"
ros2 launch turtlebot4_navigation nav2.launch.py \
  use_sim_time:=true params_file:="$PARAMS"
\end{lstlisting}
随后检查：
\begin{lstlisting}[language=bash]
ros2 param get /planner_server planner_plugins
ros2 param get /planner_server GridBased.plugin
ros2 lifecycle get /planner_server
ros2 topic info /plan -v
\end{lstlisting}
实测返回的插件为 \code{tb4\_astar\_planner/AStarPlanner}，Planner Server 状态为
\code{active [3]}，\code{/plan} 唯一发布者为 \code{planner\_server}。

\subsection{发送长距离导航目标}
在目标发送前开始全屏连续录制，保持 RViz 显示地图、机器人、LaserScan、AMCL
粒子、全局路径和代价地图，然后通过专用 action 运行器发送唯一长距离目标：
\begin{lstlisting}[language=bash]
ros2 run tb4_experiment_bringup run_long_navigation \
  --x -7.0 --y -10.0 --yaw 0.0 \
  --min-path-length 12.0 \
  --evidence "$HOME/long-navigation-result.json"
\end{lstlisting}
\code{run\_long\_navigation} 订阅同一运行中的 \code{/plan}，计算相邻位姿欧氏距离
之和；若路径短于 12.0 m，则取消 action 并判为失败。验收条件包括：
\begin{enumerate}
  \item 全局路径长度不小于 12.0 m；
  \item 路径跨越多个货架和通道，且不穿越占用或膨胀障碍；
  \item 同一条 action 最终进入 \code{SUCCEEDED (4)}，不得进入
        \code{ABORTED (6)}；
  \item JSON 同时保存目标、路径位姿数、路径长度、墙钟时长和终态；
  \item 视频从目标发送前开始，到机器人到达目标后结束，时长不少于 300 s，
        不加速、不抽帧、不删减中间运动过程。
\end{enumerate}

\subsection{仿真时钟与低负载配置分析}
启动阶段由 \code{vmware\_simulation\_validator} 连续观察 120 s 墙钟，确认
\code{/clock} 推进，且 \code{/scan} 包含 1.339--11.997 m 的环境回波；通过后
15 s 停钟 watchdog 继续运行。最终长距离 action 又持续 385.981 s 墙钟并正常结束，
完整录屏持续 443.934 s，说明本次验收期间物理、传感器、定位、规划与控制链路均
持续工作。

本机约 6 vCPU、7.7 GiB 内存且无独立 GPU。Gazebo 软件渲染、RPLIDAR、
AMCL、两套 costmap 与 RViz 同时运行时仍会竞争 CPU 和虚拟 GPU；Nav2 日志中出现
\code{Behavior Tree tick rate 100.00 was exceeded} 警告，但未导致 action 中止。
为获得可完成的端到端实验，证据采集使用了以下低负载配置：
\begin{itemize}
  \item Gazebo 以 server-only 模式运行，关闭三维客户端但保留物理、传感器和时钟；
  \item OAK-D 停用；关闭 Create 3 cliff/IR GPU lidar 及其 ROS 桥接，因为导航使用
        RPLIDAR；
  \item RPLIDAR 更新率由默认高频降至 10 Hz，\code{/scan} 始终保持发布；
  \item 不生成充电底座，不启动 TurtleBot4 HMI/传感器 lifecycle，保留 Create 3
        运动控制、里程计和 TF；
  \item 临时 world 使用 \code{max\_step\_size=0.01 s}、
        \code{real\_time\_update\_rate=20 Hz} 与
        \code{real\_time\_factor=0.2}；
  \item Create 3 controller 更新率设为 100 Hz，里程计发布率设为 20 Hz。
\end{itemize}
上述措施没有关闭 SLAM、AMCL、Planner Server、Controller Server、Velocity Smoother
或 Nav2 action，因此不改变自主导航的功能性证据；但 \code{max\_step\_size} 和激光
频率改变了仿真保真度，本报告不将其表述为默认高保真参数下的实时性能测试。建议在
具有硬件 3D 加速、至少 4 核 CPU 和 16 GiB 内存的 Ubuntu 22.04 主机上使用默认 world
与传感器参数复测，可同时打开 Gazebo GUI 进行三维演示。

\section{问题诊断与改进}

\subsection{启动参数作用域}
初始启动文件未显式转发 \code{gz\_args}，导致自定义低负载 world 未被 Gazebo 使用；
修复后又发现父级 \code{slam:=true} 会泄漏至官方子启动，从而产生两套 SLAM 节点。
将官方 simulator include 放入 scoped group 后，官方 spawn 的内部参数与项目级
SLAM/AMCL 模式完全隔离。该修改使“一个地图源、一个定位源、一个 Planner Server”
成为可重复的启动不变量。

\subsection{RViz 视角确定性}
官方配置保存了旋转后的 TopDownOrtho 角度，导致屏幕坐标与地图坐标难以对应。实验
专用 \code{experiment.rviz} 固定 \code{Fixed Frame=map}、\code{Angle=0}、
\code{X=0}、\code{Y=-1.965}，并预置 \code{SetInitialPose} 和
\code{GoalTool}。每次启动均恢复相同俯视方向，从而使初始位姿和目标点操作可复现。

\subsection{慢速主机的 lifecycle 启动顺序}
若 Nav2 抢在 AMCL 初始位姿前激活，Controller Server 可能在等待
\code{map -> odom} 时停留于 inactive。最终流程使用
\code{start\_nav2:=false} 先建立定位 TF，再单独启动 Nav2；Planner、Controller
和 BT Navigator 随后均进入 \code{active [3]}。该分阶段顺序避免把 lifecycle
阻塞误判为 A* 算法错误。

\subsection{建图范围与长路径的自动门槛}
初版只依赖人工遥控和截图，导致 0.550 m 的运动也可被描述为“完成建图”，6.872 m
路径也缺乏统一的长距离标准。改进后，\code{validate\_slam\_coverage} 将 5.0 m
累计行程和 15,000 个已知栅格增量作为双门槛；\code{run\_long\_navigation} 则在
同一 action 内强制路径长度至少为 12.0 m，并将终态写入 JSON。门槛未满足时工具
直接返回非零状态，避免仅凭机器人开始运动就判定成功。

扩展路线最初直接发布 \code{/cmd\_vel}，与已激活的 Velocity Smoother 输出形成
竞争，可能导致旋转后无法继续直行。最新版将路线输入改为 \code{/cmd\_vel\_nav}，
确保所有路线速度都经过同一平滑器，再由其唯一发布到底盘速度话题。

\subsection{雷达云漂移的量化判定}
RViz 灰显、低帧率或画面拖影不等同于 AMCL 漂移。新验证器同时测量
\code{map -> base\_link} 平移/航向变化，并使用占据地图对 LaserScan 端点进行几何
命中检查。只有 15 s 内漂移不超过 0.10 m/0.10 rad 且匹配率不低于 0.35 才允许
进入导航阶段，使“雷达云稳定”从主观观察转为可复现实验指标。

\subsection{完整视频证据保真}
最终录屏工具会同时生成短标注摘要和分段原始视频。为遵守“不加速、不剪缩”的验收
要求，报告与提交包仅使用按时间顺序无损拼接的原始分段；\code{ffprobe} 对最终 MP4
再次验证 443.934 s 时长、15 fps 和 H.264 编码。该处理只改变容器与文件分段，不
改变帧时间轴。

\subsection{后续优化方向}
\begin{enumerate}
  \item 在统一 launch 中以 TF/lifecycle 条件自动执行当前的分阶段 Nav2 启动；
  \item 为 A* 增加起点可通行性、起点等于终点且位于障碍等边界测试；
  \item 在高性能主机上恢复默认物理步长、完整 OAK-D 和默认激光频率，测量规划耗时、
        实时率与资源占用；
  \item 使用 SLAM Toolbox 的序列化 pose graph 和 continuation mapping 验证
        “加载已有地图后继续扩图”的扩展流程；
  \item 在实体 TurtleBot4 上配置 DDS/Discovery Server，复用同一 planner 插件和
        Nav2 参数进行实机验证。
\end{enumerate}

\section{结论}
本实验完成了 TurtleBot4 仿真自主导航的完整功能链：Ignition Gazebo 提供机器人、
warehouse 环境、激光雷达、里程计与物理运动；SLAM Toolbox 建立并保存增量地图；
AMCL 在静态地图上完成自定位；自定义代价感知 A* 以 Nav2 pluginlib 插件形式生成
无碰撞全局路径；DWB、速度平滑器和 Create 3 仿真底盘构成闭环执行系统。

针对助教反馈完成的量化改进为：SLAM 累计行程由 0.550 m 提升至 5.00 m，已知栅格
增量由 4,858 提升至 58,506；静止定位 15 s 内位置/航向漂移均为 0，LaserScan
地图匹配率达到 96.5\%；A* 路径由 6.872 m 提升至 13.460 m，包含 370 个位姿。
同一长距离 \code{NavigateToPose} action 经 385.981 s 墙钟时间进入
\code{SUCCEEDED (4)}，完整无加速视频时长为 443.934 s。因此，改进版本不仅完成
TurtleBot4 仿真自主导航，也对地图覆盖、路径长度、雷达稳定性和视频完整性给出了
可重复、可自动判定的证据。

本报告的结果仅适用于 VMware 低负载仿真环境。软件渲染和降频设置改变了实时性能与
传感器更新频率，不能替代默认高保真仿真或实体 TurtleBot4 的安全与性能验证。
